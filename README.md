Живой сайт: **https://kseniyavostryakova.art**

Статический сайт (чистый HTML/CSS/JS, без сборки и бэкенда), хостится на GitHub Pages.

## Структура репозитория

Корень репозитория — это **тот вариант дизайна, который сейчас показывается посетителям** (сетка работ по годам, в духе referenсa olesyarubeko.com). Два других варианта дизайна, которые обсуждались по пути, остались в репозитории как архив — код рабочий, но они не главная страница:

```
/                   ← ЖИВОЙ САЙТ (вариант «Сетка»)
  index.html          Главная (сплит: текст + фото)
  about.html          Обо мне + CV
  paintings.html      Живопись (сетка работ, лайтбокс)
  contacts.html       Контакты
  404.html            Страница 404 с зацикленным видео
  style.css, script.js
  images/             Оригиналы картин + images/thumbs/ — сжатые превью для сетки
  assets/             404-loop.mp4
  CNAME               кастомный домен (kseniyavostryakova.art)

/scroll/            ← архив: первый вариант, один бесконечный скролл
/gallery/           ← архив: второй вариант, карусель + левое меню (в духе annasladkova.com)
```

Каждый вариант — самодостаточный набор файлов (свой `style.css`, `script.js`, своя папка `images/`). Если понадобится вернуться к «Скроллу» или «Карусели» как к главной версии — просто поменять местами содержимое с корнем (как это уже делалось один раз при переходе с «Скролла» на «Сетку»).

## Как отредактировать контент (без CMS)

CMS сознательно не подключали — обсуждали (git-based CMS вроде Decap CMS реалистична, но требует переезда на генератор статики, ~1–2 дня работы). Пока редактирование — через правку HTML в `paintings.html` / `about.html` / `contacts.html`. Проще всего — попросить Claude внести правку, но если делать руками:

### Добавить новую картину

1. Кинуть фото картины в `images/` (оригинал в максимальном качестве, как есть).
2. Сделать сжатую миниатюру в `images/thumbs/` — макс. сторона ~900px, JPEG качество ~78 (см. раздел «Оптимизация изображений» ниже, как это делалось скриптом).
3. В `paintings.html` скопировать один блок `<figure>...</figure>`, поменять:
   - `data-lightbox="images/ИМЯ_ОРИГИНАЛА"` — путь к полному оригиналу (открывается в лайтбоксе)
   - `<img src="images/thumbs/ИМЯ.jpg">` — путь к миниатюре (что видно в сетке)
   - `data-ru` / `data-en` у `.title` и `.meta-inner` — название и техника/год на двух языках
4. Порядок работ в сетке — по году убывания (2026 → 2021), новую работу нужно вставить в нужное место вручную.

### Поменять био / CV / контакты

Прямая правка текста в `about.html` (блок `.bio-facts` и `.cv-section`) и `contacts.html` — везде есть парные атрибуты `data-ru="…" data-en="…"`, оба нужно менять синхронно.

## Билингвальность (RU/EN)

Реализовано без фреймворков: у переключаемых элементов два атрибута — `data-ru` и `data-en`. `script.js` при клике на RU/EN подставляет нужный текст через `textContent`. Выбор языка запоминается в `localStorage`. Логотип, названия картин без явного смысла (напр. «Confused», «Some of these days») намеренно оставлены без перевода — это имена собственные.

## Лайтбокс и «бегущая строка»

- Клик по миниатюре открывает полноэкранный просмотр (`paintings.html`, блок `.lightbox`) — подгружается **оригинал в полном качестве**, не миниатюра.
- Внутри лайтбокса есть двойной зум (лупа ± внизу справа) — доступен только для картин с большим исходным разрешением (порог — 3000px по большей стороне, см. `canZoomFurther` в `script.js`).
- Подпись «техника/год», если не помещается в ширину карточки — не переносится на новую строку, а превращается в медленную бегущую строку (3 сек пауза → прокрутка → 3 сек пауза → прокрутка обратно, зациклено). Логика — `refreshMarquees()` в `script.js`, использует Web Animations API.

## Оптимизация изображений

Оригиналы картин — тяжёлые (от 100KB до 20MB на файл, суммарно ~60MB). Сетка их не грузит напрямую — только сжатые превью:

- `images/thumbs/*.jpg` — макс. сторона 900px, JPEG качество 78, сгенерированы через Pillow (макс. сжатие ~60×, ~1MB суммарно на все 17 превью).
- Оригиналы остаются в `images/` как есть — подтягиваются лениво, только при открытии конкретной картины в лайтбоксе.
- Прелоад на главной странице (`script.js`, `PAINTING_IMAGES`) тоже грузит только миниатюры — чтобы к моменту перехода на страницу «Живопись» сетка была уже в кэше браузера.

Если добавляете новую картину — не забудьте сделать для неё уменьшенную копию в `thumbs/`, иначе сетка снова начнёт грузить оригинал напрямую.

## Что сознательно отложено

- **Аналитика посещений** — не подключена. Обсуждали Cloudflare Web Analytics / Plausible (лёгкие, без cookie-баннера) как более уместные для этого сайта варианты, чем Google Analytics. Готово к подключению за 10 минут, когда понадобится.
- **CMS для самостоятельного редактирования** — отложена. Технически это git-based CMS (Decap CMS) поверх статического генератора — реалистично, но требует архитектурного изменения (~1–2 дня работы). Пока контент правится через код.
